6. MULTI-ID PACKAGE LOGIC — LOCKED
==================================================

Higher packages create multiple IDs.

External sponsor connects to the buyer's FIRST ID only.

The buyer's first ID then internally sponsors package-generated IDs according to the package structure.

Turbo example:

Turbo = 4 IDs

External sponsor
↓
Buyer ID 1
↓
Buyer ID 2
Buyer ID 3
Buyer ID 4

Meaning:
- External sponsor earns commission from Buyer ID 1 only
- Buyer ID 1 sponsors Buyer IDs 2, 3, 4
- Those 3 IDs complete Buyer ID 1's Level 1

Do not treat the external sponsor as sponsor of all 4 IDs.

Super Turbo:
13 IDs

Structure includes:
- Root / first ID
- Next 3 IDs under first ID
- Next 9 IDs under those positions

Total = 13 IDs

Hyper Turbo:
22 IDs

The exact complete internal placement map beyond the already-confirmed logic is not fully specified.

Therefore:
- Build the architecture so Hyper Turbo placement rules can be configured
- Do not invent an irreversible unsupported placement structure
- Admin/system configuration should allow future approved placement definition

11. GLOBAL COMMISSION HOLD & RELEASE RULE — LOCKED
==================================================

This applies to ALL levels.

Commission accumulates member by member.

It is NOT released immediately.

It remains in:
HELD / PENDING COMMISSION

until the required member count for that level is fully completed.

Then:

FULL ACCUMULATED LEVEL COMMISSION
→ RELEASED TO WALLET

Pattern:

Generate
→ Accumulate
→ Hold
→ Complete
→ Release

Do not partially release a level's commission before that level is completed.
